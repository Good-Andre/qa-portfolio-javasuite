# 🎮 Обратная связь от плейтестов (Playtest Feedback)

Документ фиксирует субъективную обратную связь от тестировщиков, UX-проблемы, баланс сложности и предложения по улучшению. Все отзывы привязаны к механикам пазла и стилистике (постапокалипсис/киберпанк).

---

## 📝 Шаблон записи обратной связи

- **Тестировщик:** Имя / псевдоним
- **Роль:** Игрок / UX-специалист / QA
- **Платформа:** Web / Windows
- **Конфигурация:** Аппаратные данные
- **Уровень:** Какой уровень тестировался
- **Общее впечатление:** 1–5 (или текст)
- **Что понравилось:** Позитивные моменты
- **Что не понравилось:** Проблемы, неудобства
- **Предложения по улучшению:** Идеи и правки
- **Эмоциональный отклик:** Атмосфера, вайб, соответствие сеттингу

---

## 💬 Примеры обратной связи

### PT-001: Тестировщик «CyberCat» (UX-специалист)

- **Тестировщик:** CyberCat
- **Роль:** UX-специалист
- **Платформа:** Windows Desktop (Impeller)
- **Конфигурация:** Windows 11, NVIDIA RTX 3060, 2560×1440
- **Уровень:** Уровень 1–3
- **Общее впечатление:** 4/5
- **Что понравилось:**
  - Плавность Drag & Drop, хорошая отзывчивость.
  - Визуальный фидбек при правильной сборке (лёгкая вибрация/свечение).
  - Атмосфера постапокалиптического киберпанка: приглушённые цвета, «грязные» текстуры, неоновые акценты.
- **Что не понравилось:**
  - Экран победы появляется слишком резко, нет плавного перехода.
  - На ультрашироком экране (21:9) элементы пазла выглядят слишком мелкими.
  - Кнопка «Отмена хода» не имеет иконки, её сложно заметить.
- **Предложения по улучшению:**
  - Добавить анимацию появления экрана победы (Fade-in + лёгкий эффект «цифрового сбоя»).
  - Масштабировать элементы пазла в зависимости от ширины экрана.
  - Добавить иконку Undo и сделать кнопку крупнее.
- **Эмоциональный отклик:** «Вайб киберпанка чувствуется, но UI местами слишком минималистичен — хочется больше „цифровых“ деталей».

### PT-002: Тестировщик «PostApocFan» (обычный игрок)

- **Тестировщик:** PostApocFan
- **Роль:** Обычный игрок
- **Платформа:** Web (Chrome)
- **Конфигурация:** Chrome 152, Windows 11, 1920×1080
- **Уровень:** Уровень 1–2
- **Общее впечатление:** 3/5
- **Что понравилось:**
  - Механика «магнита» при установке элемента — удобно.
  - Неоновая палитра и цветовая кодировка фрагментов (помогает ориентироваться).
- **Что не понравилось:**
  - Сложность растёт слишком резко между 1 и 2 уровнем.
  - Нет подсказки о том, как работает «Отмена хода».
  - Иногда элементы «залипают» при перетаскивании.
- **Предложения по улучшению:**
  - Сделать более плавный рост сложности (добавить промежуточные уровни).
  - Добавить краткую подсказку при первом использовании Undo.
  - Улучшить обработку Drag & Drop — убрать микро-задержки.
- **Эмоциональный отклик:** «Атмосфера нравится, но механика местами раздражает — хочется более интуитивного управления».

### PT-003: Тестировщик «Zero» (QA-инженер)

- **Тестировщик:** Zero
- **Роль:** QA-инженер
- **Платформа:** Windows Desktop (Skia)
- **Конфигурация:** Windows 10, Intel UHD, 1366×768
- **Уровень:** Уровень 1–4
- **Общее впечатление:** 4/5
- **Что понравилось:**
  - Стабильная работа на слабом железе.
  - Чёткие визуальные подсказки при коллизиях.
- **Что не понравилось:**
  - При сворачивании окна прогресс иногда сбрасывается.
  - Анимации на низких FPS выглядят дёргаными.
- **Предложения по улучшению:**
  - Оптимизировать анимации для низких FPS (или отключать сложные эффекты при <45 FPS).
  - Исправить баг с потерей прогресса.
- **Эмоциональный отклик:** «Игра хорошо оптимизирована для слабых ПК, но есть критические баги, которые портят впечатление».

## 💡 Рекомендации по использованию

1. **Для баг-репортов:** Заполняй все поля, особенно «Аппаратные данные» и «Шаги воспроизведения» — это критично для Flame-игр, где поведение может зависеть от GPU и FPS.
2. **Для плейтестов:** Собирай обратную связь от разных типов игроков (обычные игроки, UX-специалисты, QA). Это даст более полную картину.
3. **Связь с лорами и механиками:** В обратной связи учитывай сеттинг — игроки ожидают определённого «вайба» от постапокалиптического киберпанка, и это влияет на восприятие UI и механик.
4. **Интеграция с автоматизацией:** Критические баги (например, краши) должны быть покрыты автотестами (widget/integration) после исправления.

# 🗺 Чек-лист ключевых механик и логики (Core Gameplay)

Проверка игровой механики, физики и логики уровней. Чек-лист построен вокруг цикла `update()` / `render()` Flame Engine и lifecycle компонентов (`onLoad` → `update` → `render`).

---

## 1. Взаимодействие с элементами (Input & Physics)

Проверка миксинов `Draggable`, `HasTappables`, `HasCollidables` и обработки событий в `onDragUpdate` / `onTapDown`.

- [ ] **Позитивный:** Элемент пазла корректно выделяется (подсвечивается) при наведении курсора / таче (`onTapDown` срабатывает без задержки).
- [ ] **Позитивный:** Перетаскивание (Drag & Drop) через `Draggable`-миксин происходит плавно, без рывков и «залипаний». Позиция элемента обновляется в `onDragUpdate` синхронно с `update()`.
- [ ] **Позитивный:** Анимация возврата элемента на исходную позицию (`onDragEnd`) проигрывается корректно — элемент плавно «магнитится» к ближайшей ячейке.
- [ ] **Граничные значения:** Попытка перетащить элемент за пределы игрового поля — элемент должен возвращаться на исходную позицию или магнититься к ближайшему краю. Проверка в `onDragEnd` через координаты границ.
- [ ] **Граничные значения:** Перетаскивание элемента с минимальным смещением (1–2 px) — не должно запускать анимацию перемещения, элемент остаётся на месте.
- [ ] **Негативный:** Быстрые хаотичные клики по элементам во время анимации их движения — не должно вызывать зависания `update()`-цикла или краша игры.
- [ ] **Негативный:** Перетаскивание элемента за пределы окна браузера / десктопного окна с последующим возвратом курсора — элемент не должен «потеряться» или зависнуть в некорректной позиции.
- [ ] **Коллизии:** Попытка поставить два элемента в одну ячейку поля — система должна блокировать действие или менять элементы местами (проверка `CollisionCallback` / `onCollisionStart`).
- [ ] **Коллизии:** Одновременное перетаскивание двух элементов в одну ячейку (race condition) — игра должна обрабатывать очередность действий, а не уходить в бесконечный цикл.

## 2. Игровая логика и правила (Game Rules)

Проверка бизнес-логики в `update()` и корректности триггеров.

- [ ] **Условие победы (Win Condition):** При сборке правильной комбинации мгновенно срабатывает триггер победы — появляется экран «Уровень пройден» (через `Overlay` или `Router`).
- [ ] **Условие победы:** Победа не срабатывает раньше времени — при частично собранной комбинации экран победы не появляется.
- [ ] **Условие поражения (Lose Condition):** При исчерпании лимита ходов / времени игра корректно блокирует поле и предлагает перезапуск (через `Overlay`).
- [ ] **Кнопка «Сброс» (Restart / Reset):** Мгновенно возвращает все элементы в исходное для уровня состояние. Счётчик ходов / времени обнуляется. Компоненты Flame полностью пересоздаются, а не сохраняют старое состояние.
- [ ] **Начисление очков / звёзд:** Расчёт финального счёта корректно зависит от количества потраченных ходов (проверка формулы: `score = baseScore - movePenalty` или аналогичной).
- [ ] **Начисление очков:** При прохождении уровня с минимальным числом ходов начисляется максимальный счёт / 3 звезды.
- [ ] **Таймер:** Если уровень имеет ограничение по времени, таймер корректно останавливается при победе и не продолжает «тикать» в фоне на экране победы.
- [ ] **Целостность уровня:** Количество элементов на поле соответствует конфигурации уровня — нет лишних или пропавших элементов после загрузки.

## 3. Сохранение данных и прерывания (State & Interruptions)

Проверка управления состоянием игры, сохранения прогресса и обработки lifecycle-событий платформы.

- [ ] **Разблокировка уровней:** При прохождении Уровня 1 автоматически разблокируется Уровень 2 в меню выбора. Сохранение в `shared_preferences` / `hive` / файл.
- [ ] **Пауза:** Вызов меню паузы замораживает таймер игры и блокирует перемещение элементов на фоне (`update()` приостановлен, `render()` продолжает отрисовывать статичный кадр).
- [ ] **Пауза:** Возобновление после паузы корректно продолжает игру — таймер не «догоняет» прошедшее время, элементы остаются в тех же позициях.
- [ ] **Hard прерывание (закрытие вкладки / окна):** Закрытие игры посреди уровня. При следующем запуске состояние либо восстанавливается (автосохранение), либо уровень начинается заново без повреждения файла сохранений (Save File Corruption).
- [ ] **Hard прерывание:** Принудительное завершение процесса (через Диспетчер задач) — файл сохранения не должен повредиться. Проверка атомарности записи (запись во временный файл → rename).
- [ ] **Множественные сохранения:** Сохранение прогресса при прохождении нескольких уровней подряд — каждое сохранение не перетирает данные о ранее пройденных уровнях.
- [ ] **Очистка кэша (Web):** Очистка кэша браузера / LocalStorage — игра должна корректно обработать отсутствие сохранения и запустить с чистого состояния, а не крашиться.

## 4. Анимации и визуальные эффекты

Проверка `FlameAnimation` / `Effect`-системы и корректности отрисовки.

- [ ] **Плавность анимаций:** Анимация перемещения элементов проигрывается без рывков при стабильном 60 FPS.
- [ ] **Прерывание анимации:** Новое действие игрока во время проигрывания анимации — анимация должна либо досрочно завершиться, либо быть отменена без визуальных артефактов (проверка `EffectController`).
- [ ] **Z-order:** Элемент, который игрок перетаскивает, должен отрисовываться поверх остальных (проверка `priority` в Flame `Component`).
- [ ] **Подсветка целевой позиции:** При наведении элемента на правильную ячейку — визуальный фидбек (подсветка, контур) появляется без задержки.
- [ ] **Экран победы:** Анимация перехода на экран «Уровень пройден» не прерывает звуковые эффекты и не вызывает повторного срабатывания триггера победы.

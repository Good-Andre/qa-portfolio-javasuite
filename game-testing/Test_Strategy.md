# 📐 Стратегия тестирования (Test Strategy)

## 1. Область тестирования (Scope)

### В области (In Scope)

- **Игровая механика:** перемещение, вращение, коллизии элементов, drag & drop
- **Игровая логика:** условия победы и поражения, подсчёт очков, лимит ходов
- **Навигация:** главное меню, выбор уровня, экраны победы и поражения
- **Сохранение прогресса:** разблокировка уровней, автосохранение, восстановление сессии
- **Кроссплатформенность:** Web (Chrome, Firefox) и Windows (standalone .exe)
- **Графические движки:** сравнительное тестирование Impeller и Skia на Windows
- **Производительность:** FPS, потребление памяти, время загрузки уровней
- **UX и баланс:** кривая сложности, визуальный фидбек, эргономика интерфейса

### Вне области (Out of Scope)

- Интеграция с платёжными шлюзами (прототип без микротранзакций)
- Мультиплеер и сетевые функции (одиночная игра)
- Локализация (прототип на одном языке)
- Нативные мобильные платформы iOS / Android — запланированы на следующую стадию

## 2. Типы тестирования

| Тип | Метод | Инструменты и артефакты |
| :--- | :--- | :--- |
| Функциональное | Ручное | `Game_Core_Checklist.md` |
| Кроссплатформенное | Ручное | `CrossPlatform_Matrix.md` |
| Сравнение рендереров (Impeller vs Skia) | Ручное + мониторинг | Flutter DevTools, Dart DevTools Profiler |
| UX и баланс | Плейтесты | `Playtests_Feedback.md` |
| Производительность | Ручное + мониторинг | Chrome DevTools (Web), Диспетчер задач / MSI Afterburner (Windows) |
| Регрессионное | Автоматизированное | `flutter test` (widget), `integration_test` |
| Визуальная регрессия | Автоматизированное | Golden tests (`matchesGoldenFile`) |

## 3. Риск-матрица

| Риск | Вероятность | Влияние | Приоритет | Митигация |
| :--- | :--- | :--- | :--- | :--- |
| Краш при коллизии элементов (race condition в `update()`) | Высокая | Blocker | 🔴 Критический | Стресс-тест инпута, проверка очереди действий |
| Потеря сохранения при закрытии вкладки / сворачивании | Средняя | Critical | 🔴 Высокий | Тестирование прерываний на обеих платформах |
| Утечка памяти при длительной сессии (компоненты Flame не удаляются) | Средняя | Major | 🟡 Средний | Профилирование сессий 30+ минут |
| Визуальные артефакты при переключении Impeller → Skia | Средняя | Minor | 🟢 Низкий | Сравнительное тестирование рендереров, скриншот-сравнение |
| UI плывёт при нестандартных разрешениях (4:3, 21:9) | Высокая | Minor | 🟢 Низкий | Проверка через кроссплатформенную матрицу |
| Зависание анимации при хаотичных кликах в процессе `update()` | Средняя | Major | 🟡 Средний | Негативные сценарии инпута в чек-листе |

## 4. Критерии приёмки

### Entry-критерии (когда начинаем тестировать)

- Сборка успешно компилируется и запускается на обеих платформах
- Ключевая механика (перемещение элементов) реализована и работает на базовом уровне
- Доступны минимум 3 тестовых уровня с разной сложностью
- Оба графических бекенда (Impeller и Skia) доступны для переключения при запуске

### Exit-критерии (когда заканчиваем)

- 100% пунктов `Game_Core_Checklist.md` проверены и отмечены
- Нет открытых багов с Severity = Blocker или Critical
- Баги с Severity = Major задокументированы, приоритизированы и имеют план исправления
- Кроссплатформенная матрица пройдена для всех целевых платформ
- Сравнение Impeller vs Skia завершено, результаты задокументированы в `CrossPlatform_Matrix.md`
- Проведён минимум один плейтест с зафиксированной обратной связью

## 5. Окружение

| Платформа | Конфигурация | Графический бекенд |
| :--- | :--- | :--- |
| Web | Chrome 152+, Firefox 130+ (Flutter Web, CanvasKit) | CanvasKit (фиксированный) |
| Windows — конфигурация 1 | Windows 10/11, интегрированная графика Intel | Impeller + Skia |
| Windows — конфигурация 2 | Windows 10/11, дискретная графика NVIDIA / AMD | Impeller + Skia |

> **Примечание:** На Web-платформе Flutter использует CanvasKit, переключение между Impeller и Skia не применяется. Сравнение рендереров проводится только на Windows-сборках.

## 6. План автоматизации

| Область | Тип теста | Приоритет | Статус |
| :--- | :--- | :--- | :--- |
| Логика расчёта очков | Widget test (`flutter test`) | Высокий | Запланировано |
| Условия победы и поражения | Widget test | Высокий | Запланировано |
| Сохранение и загрузка прогресса | Integration test | Средний | Запланировано |
| Визуальная регрессия UI | Golden test | Низкий | Запланировано |
| Игровой цикл E2E | `integration_test` | Средний | Запланировано |

Автоматизация выполняется в рамках Flutter-проекта на Dart, отдельного от Java-портфолио.

## 7. Методология сравнения Impeller vs Skia

Сравнение двух графических движков проводится на Windows-сборках с целью определить оптимальный бекенд для релиза.

### Параметры сравнения

| Параметр | Как измеряется | Целевое значение |
| :--- | :--- | :--- |
| Средний FPS | Dart DevTools PerformanceOverlay | ≥ 60 FPS |
| Стабильность FPS (1% lows) | Ручной замер при сложных сценах | Не ниже 45 FPS |
| Потребление ОЗУ | Диспетчер задач, 10-минутная сессия | Не более 350 МБ |
| Время отрисовки кадра | Flutter DevTools Timeline | < 16 мс (для 60 FPS) |
| Визуальные артефакты | Визуальный осмотр + скриншот-сравнение | Отсутствуют |
| Время загрузки уровня | Ручной секундомер | < 2 с |

### Процедура

1. Запустить Windows-сборку с флагом `--enable-impeller` (Impeller).
2. Провести 10-минутную сессию: 3 уровня, стресс-тест инпута, проверка паузы и возобновления.
3. Зафиксировать метрики из таблицы выше.
4. Перезапустить сборку с флагом `--no-enable-impeller` (Skia).
5. Повторить шаги 2–3 на тех же уровнях и сценариях.
6. Повторить на обеих конфигурациях (Intel и NVIDIA/AMD).
7. Результаты зафиксировать в `CrossPlatform_Matrix.md` в разделе «Сравнение рендереров».

### Критерий выбора

По итогам сравнения выбирается бекенд, который демонстрирует:

- Стабильный FPS без просадок ниже 45 FPS
- Меньшее потребление памяти
- Отсутствие визуальных артефактов (рывки, пропадание текстур, артефакты прозрачности)

Если оба бекенда показывают сопоставимые результаты, предпочтение отдаётся Impeller как более современному движку с активной разработкой со стороны Flutter-команды.
